# Haccora UK launch and business services — 15 September 2026

## Release changes

- Integrates the pending security work and Veyumo bridge, keeping the immutable migration history.
- Adds 12 optional business services and contextual owner-only recommendations across ten screens.
- Provides search, category filters, service details and consented requests in the existing tenant support workflow. Multi-service quotes are requests, not automatic discounts.
- Owner authorisation, verified organisation context, consent validation and duplicate prevention run in PostgreSQL. Another tenant cannot list requests. Resolving a request does not activate a subscription.
- Reuses TaxNuvia's `/from/haccora` referral flow; no profile information or tokens are put in referral links.
- Veyumo connects only when the owner opens its panel. Existing private Stripe keys remain in Lovable; Haccora does not assert a mobile discount entitlement until a signed billing integration exists.
- Corrects the production CSP to permit embedded Stripe checkout while retaining anti-framing, inline-event and other security controls.
- Updates vulnerable js-yaml and xmldom dependencies. An unavailable registry audit now fails closed.

## Deployment

1. Merge after the repository checks pass. Publish the synced application through Lovable.
2. Apply `20260915100000_business_service_requests.sql` after all existing migrations. Deploy the updated Edge Functions, including `veyumo-bridge`.
3. Complete `docs/github-production-configuration.md`. The latest inspected scheduled-dispatch run (`34938260903`) fails because both `SUPABASE_URL` and `CRON_SECRET` are empty. Do not disable the guard.
4. Verify protected role persistence, dashboards, Stripe lifecycle, email/push delivery and dispatcher heartbeats against the published release.
5. Follow `docs/VEYUMO.md` for the separate Omniqora/Gigs provider configuration. Keep mobile sales and bundle claims disabled until that path is verified.

## Observed limitations

The public uptime workflow is passing. This is not evidence that hosted role isolation, provider delivery, payments, migration state or the complete go-live checklist have passed. Supabase and Lovable account connections are needed to complete and inspect protected hosted setup. The Omniqora AI workspace is an owner-private pilot and is therefore not exposed as a customer destination. Accountants and recruitment open their own services; supplier and other integrations initially use an enquiry workflow.

Local Chromium download is unavailable in this environment. Browser and fresh-database checks run in repository CI; production acceptance still needs the designated test identities and provider configuration. Native export is build validation, not App Store or Play Store approval.
