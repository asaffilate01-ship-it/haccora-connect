# Phase 61 — Operational label safety and live evidence workbench

## Delivered in code

- Removed the five fabricated sample foods, assumed shelf-life days and unsupported allergen declarations from the operational print screen.
- Only real organisation/premises recipe records can be selected. Missing workspace, RLS/read failures, flagged recipes and mismatched site/org prevent a print request.
- The operator enters a real use-by date and explicitly confirms a check against the current recipe and food-safety procedures. Date validation uses the premises' local day, including UK/German summer-time changes. No automatic shelf-life calculation.
- Immediately before issuing a request the client re-reads the selected recipe, rejects changed/missing source evidence and checks the current permissions/context again.
- Existing `label_prints` history is persisted with site, organisation, operator and idempotency key. The preview appears only after a returned saved row; the final print action is an explicit user click and expires after 60 seconds.
- Print CSS hides the surrounding application and isolates a single operational label. The display explicitly says a print request is **not proof of physical printing**.
- Allergen / PPDS labels are intentionally excluded from this generic workbench: `haccora-connect` points to the existing controlled PPDS review workflow; Germany requires a governed ingredient/specification approval workflow before allergen labels can be activated.
- Pure-data regression tests cover cross-tenant and cross-location recipe selection, dated evidence, missing review, expired dates, disabled accounts, and unauthorised allergen-print kinds.

## Safety, RLS and release limits

- Client checks provide UX safeguards; they are **not** a substitute for database RLS, atomic supplier-approval checks, or an independent food-safety review.
- Source re-read cannot guarantee that a recipe or ingredient is unchanged between the final check and a physical print. A production-grade controlled label service should validate and save the snapshot transactionally on the server and support physical printer acknowledgement/withdrawal.
- `label_prints` records a print **request**, not an actual printer acknowledgement or fully traced recipe-version approval. The new UI avoids representing it as proven printing.
- Only approved specialist-reviewed labels should include a full allergen/PPDS declaration. The operational label's absence of allergens is **not** an allergen-free claim.
- The UK application must retain PPDS ingredient-specification version checks, evidence gating and four-nation compliance-content separation. Germany requires local LMHV/IfSG and EU hygiene review. Do not treat compliance certificates or regulatory approval as generated by software.
- No schema migrations or credentials were added. Apply to an isolated staging tenant first; test owner/manager/chef/staff/inspector permissions, real print output, off-premises access, role changes, browser storage, keyboard, touch and offline conditions before deployment.
